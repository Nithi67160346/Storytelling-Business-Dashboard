รายการสินค้าที่ต้องตัดสินใจ

สินค้าที่ต้องจัดการ ผลกระทบถ้าไม่ทำ และ action ที่แนะนำ

ระดับความเสี่ยง สินค้า / รหัส SKU สัญญาณที่ตรวจพบ (Signal) ผลกระทบทางธุรกิจหากไม่ทำ Action ที่ต้องดำเนินการ การอนุมัติ
แหล่งข้อมูล: ไฟล์ CSV ในโฟลเดอร์ datasets/ (ข้อมูลจำลอง) Grain: รายวัน × สินค้า × ภูมิภาค นิยาม KPI: กดปุ่ม ℹ ที่การ์ด KPI เพื่อดูสูตร เป้าหมาย และผู้รับผิดชอบ

ข้อมูลที่ใช้ (Data Warehouse & Star Schema)

โครงสร้างตาราง Fact, Dimensions, Data Dictionary และตัวอย่างข้อมูล

ไฟล์ข้อมูลที่ใช้ (ข้อมูลจำลอง 3 สถานการณ์: คงที่ / ตามฤดูกาล / พุ่งจากโรคระบาด)

ไฟล์ทั้งหมดอยู่ในโฟลเดอร์ datasets/ ของ repository

Star Schema

Grain: Daily Transaction per Product SKU per Regional DC Hub

dim_product Dimension

  • product_key (PK): INT
  • product_code: VARCHAR(20)
  • product_name: VARCHAR(100)
  • category: VARCHAR(50)
  • unit_cost: DECIMAL(10,2)
  • shelf_life_days: INT

dim_region Dimension

  • region_key (PK): INT
  • region_code: VARCHAR(10)
  • region_name: VARCHAR(50)
  • dc_hub_name: VARCHAR(50)
  • lead_time_days: INT

fact_demand_sales Fact Table

  • sales_fact_id (PK): BIGINT
  • date_key (FK): INT
  • product_key (FK): INT
  • region_key (FK): INT
  • scenario_key (FK): INT
  • [Measure] sales_quantity: INT
  • [Measure] inventory_snapshot: INT
  • [Measure] forecast_demand_qty: INT
  • [Measure] stock_cover_days: DECIMAL(5,1)
  • [Measure] safety_stock_threshold: INT
  • [Measure] revenue_thb: DECIMAL(12,2)

dim_date Dimension

  • date_key (PK): INT (YYYYMMDD)
  • full_date: DATE
  • day_of_week: VARCHAR(15)
  • calendar_month: INT
  • is_outbreak_period: BOOLEAN

dim_scenario Dimension

  • scenario_key (PK): INT
  • scenario_name: VARCHAR(50)
  • epidemic_index: DECIMAL(4,2)
  • macro_multiplier: DECIMAL(4,2)

Data Dictionary & Semantic Definition (พจนานุกรมข้อมูล)

ชื่อคอลัมน์ (Column Name) ตาราง ชนิดข้อมูล Grain / ระดับข้อมูล คำอธิบายทางธุรกิจ / สูตรการคำนวณ
sales_quantity fact_demand_sales INT ยอดขายรายวัน จำนวนหน่วยสินค้าที่ส่งมอบให้ลูกค้าสำเร็จในแต่ละวัน
inventory_snapshot fact_demand_sales INT สต็อกคงคลัง ณ สิ้นวัน ระดับสินค้าพร้อมจำหน่ายที่ตัดยอด ณ เวลา 23:59 น.
stock_cover_days fact_demand_sales DECIMAL วันครอบคลุมสต็อก inventory_snapshot / (30D Forecast / 30)
wape_percent fact_model_eval DECIMAL Holdout WAPE Error (Σ|Actual - Forecast| / Σ Actual) * 100
epidemic_index dim_scenario DECIMAL ดัชนีตรวจจับการระบาด ดัชนีคำค้นหาและสถิติผู้ป่วยจากกระทรวงสาธารณสุข

Dashboard Brief Canvas

ใครใช้ ตัดสินใจอะไร ดู KPI อะไร และเห็นแล้วทำอะไรต่อ

1. User (ใครเป็นคนดูจอ?)

Supply Chain Planner & VP Operations

Tactical Persona: Supply Chain Planner ดูจอทุกเช้า เพื่อตรวจสอบ Performance Gap และหาสาเหตุ (Root Cause)

Strategic Persona: VP of Operations ดูภาพรวมรายเดือน เพื่อตัดสินใจงบประมาณจัดซื้อและบริหารความเสี่ยงระดับประเทศ
2. Decision (ต้องตัดสินใจอะไร?)

ปรับแผนจัดซื้อฉุกเฉิน & ย้ายสต็อก

1) ต้องออกใบสั่งซื้อเร่งด่วน (Expedite PO) สำหรับสินค้าใด และจำนวนเท่าใด?

2) ศูนย์กระจายสินค้าใดสามารถโอนย้ายสต็อกส่วนเกิน (Buffer Stock Transfer) มาช่วยพื้นที่วิกฤตได้ทันที?
3. Metric (KPI หลัก 3-5 ตัว)

KPIs พร้อมเกณฑ์ Target ชัดเจน

1. Stock Cover Days: เกณฑ์ ≥ 21 วัน (ปกติ), < 21 วัน (เตือน), < 15 วัน (วิกฤต)
2. 30-Day Forecast: ยอดคาดการณ์เทียบงบประมาณ
3. WAPE Accuracy: เป้าหมาย ≥ 90%
4. Critical SKUs: เป้าหมาย 0 SKU
4. Grain (ข้อมูลระดับใด?)

Daily x SKU x Regional DC

ข้อมูลจัดเก็บในระดับรายวัน (Daily Fact) ต่อรหัสสินค้า (SKU) ต่อศูนย์กระจายสินค้า (Regional DC)

ทำให้สามารถ Drilldown จากภาพรวมประเทศลงสู่รายสาขาและรายสินค้าได้ทันทีโดยไม่เสียความถูกต้อง
5. Dimension (ต้องตัดมุมมองด้วยอะไร?)

4 มิติการตัดมุมมอง

1. Product: หมวดหมู่ (Diagnostic, Protection), รหัส SKU
2. Geography: กรุงเทพฯ, ภาคกลาง, ตะวันออก, เหนือ, ใต้
3. Time Horizon: 30 วัน, 60 วัน, 90 วัน
4. Scenario: โรคระบาดฉับพลัน, ฤดูกาลปกติ, ซัพพลายสะดุด
6. Action (เห็นแล้วทำอะไรต่อ?)

Action ทางธุรกิจที่ชัดเจน

1. One-Click PO Expedite: กดอนุมัติเพื่อบันทึกคำขอสั่งซื้อเร่งด่วน
2. Inter-DC Stock Transfer: ขอโอนย้ายสินค้าข้ามคลัง
3. ป้องกัน Stockout: รักษา SLA และลดความสูญเสียยอดขาย

เหตุผลที่เลือกชาร์ต

1. Main Story Chart (Line + Area):

เลือก Line Chart เพื่อแสดง Trend over time เปรียบเทียบ Actual vs Forecast พร้อมเส้น Threshold สองระดับ เพื่อให้สมองมองเห็นช่องว่างความเสี่ยงในเสี้ยววินาที

2. Sorted Bar Chart:

เลือก Sorted Horizontal Bar Chart สำหรับ Stock Cover Days เพราะ Length และ Position ทำให้อ่านและเปรียบเทียบความเสี่ยงของแต่ละ SKU ได้แม่นยำที่สุด

3. Alert & Exception Design:

ออกแบบระบบแจ้งเตือนแบบ Action-Oriented ระบุชัดเจนว่าใครต้องรับ ผลกระทบคืออะไร และมีปุ่ม Take Action ทันที ป้องกัน Anti-pattern ปล่อยสัญญาณเตือนค้างไว้
